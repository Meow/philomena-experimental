# Context-policy migration ledger

This Phase 0 ledger inventories every can?/3 occurrence under lib/philomena_web. It includes the legacy AppView.can?/3 definition and its Canada adapter call, for 126 occurrences at inventory time. Each row is one occurrence.

Adjacent predicates record neighboring state, role, ownership, preference, and sensitive-field checks participating in the same decision. Type is one of access, disclosure, affordance, or presentation. Targets are migration destinations, not implementation commitments.

## Adjacent predicate index

These non-Canada predicates are retained as explicit migration inputs rather
than being treated as cosmetic template logic:

- **Identity and moderation disclosure:** `hidden_from_users`,
  `destroyed_content`, `approved`, `deleted_by`, `locked_by`, `ip`,
  `fingerprint`, `hide_staff_tools?(@conn)`, `link.public`,
  `@rule.hidden`/`@rule.internal`, and DNP `hide_reason` appear beside the
  image, communication, attribution, rule, tag-change, source-change, and
  DNP rows above (for example `templates/comment/_comment.html.slime:2-46`,
  `templates/post/_post.html.slime:2-45`, and
  `templates/topic/show.html.slime:6-89`).
- **Ownership and actor identity:** `current?/2`,
  `@message.from_id == @conn.assigns.current_user.id`, private-link
  `public` checks, commission owner checks, and report assignment checks are
  adjacent to profile, commission, message, report, and gallery controls
  (`templates/profile/show.html.slime:4-106`,
  `templates/profile/commission/_listing_sidebar.html.slime:64-73`,
  `templates/message/_message.html.slime:27`, and
  `templates/admin/report/show.html.slime:51`).
- **Role and role-map gates:** `@user.role`, `@current_user.role`,
  `tag_change.user.role`, and `source_change.user.role` affect staff labels,
  profile administration, ban controls, and attribution disclosure
  (`templates/profile/_admin_block.html.slime:170-176`,
  `templates/admin/user/_list.html.slime:27`,
  `views/tag_change_view.ex:24`, and `views/source_change_view.ex:7`).
- **State and hard limits:** `@changeset`, `current_ban`, `mergeable?/1`,
  filter/gallery/channel state, DNP `aasm_state`, and the topic post cap
  (`@topic.post_count < 200_000`) plus `@bans`/history collection presence
  constrain the adjacent
  forms, links, and sections.
- **Output-format redaction:** JSON views independently branch on hidden
  images/topics/posts/comments, destroyed comments, public artist links, and
  public profile links (`views/api/json/image_view.ex:22-54`,
  `views/api/json/comment_view.ex:17-35`,
  `views/api/json/forum/topic_view.ex:16`,
  `views/api/json/forum/topic/post_view.ex:25-38`, and
  `views/api/json/artist_link_view.ex:4`). These are disclosure entries for
  the same context projections even though they contain no `can?/3` call.

## Contradictions to resolve during migration

The current broad predicates combine decisions that should become separate
result fields:

- `:hide` simultaneously exposes destroyed/deleted communication content and
  offers hide, restore, and delete-content controls (rows 011-014, 018-021,
  and 053-056).
- Duplicate-report `:edit` gates both report operations and modifier/reporter
  identity disclosure (rows 028-030).
- Message `:approve` is used both for the approval affordance and for pending
  body disclosure, alongside a sender-ID comparison (rows 049-050).
- Image `:show`/`:hide` is passed into URL builders, so one boolean controls
  media disclosure and hidden-image access rather than a typed media
  projection (rows 037-038 and 095-099).
- Class-level user gates control email disclosure and unrelated per-row links
  (rows 004-007); the eventual user/list entries must split those fields and
  actions.
